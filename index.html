Enterprise-readiness

Most AI portfolios stop at "it works." Mine is built against an eight-dimension readiness framework — the gap between a prototype and production in any regulated enterprise. The framework is industry-agnostic; every project below is scored against it, honestly.

01

OWASP LLM Top-10: input/output guardrails, injection defense, instruction/data separation.

04

Interchange

ai-portfolio / interchange-ai ↗
Governed knowledge runtime

Problem. Answer questions over X12/EDI & rail rules — deliberately one of the most arcane regulated domains there is: if a governed knowledge runtime holds here, it holds in your industry. "Naive RAG" is dead; this is a knowledge runtime.

Controls. Input guardrail (injection heuristics), instruction/data separation, an output grounding check that flags anything uncited, and a per-request audit log with token cost and latency.

Shipped. An MCP tool server, hybrid retrieval (dense + BM25), offline retrieval eval and an advisory graded answer-quality check, and opt-in OpenTelemetry tracing. Also shipped: measured retrieval ablations, corpus profiles as portable data, and explicit context assembly.

At scaleA LangGraph agent orchestrating the retrieval loop, and AWS Bedrock in-VPC.

Defensive security lab

Problem. Prompt injection is genuinely unsolved. A hands-on lab: a deliberately-vulnerable RAG app, four documented attacks, and the layered defenses that stop each — fully offline, no keys.

Controls. Direct + indirect (RAG-poisoning) injection, secret exfiltration, insecure-output handling — each paired with the defense that stops it. A runner prints a PASS/FAIL table: lands undefended, blocked defended.
